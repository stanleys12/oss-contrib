Prioritise opportunities in this repository's **post-quantum cryptography** code paths, in this order of preference:
ML-KEM / Kyber (key generation, encapsulation, decapsulation, encoding/decoding, implicit rejection), ML-DSA / Dilithium, SLH-DSA / SPHINCS+, FN-DSA / Falcon, hybrid key exchange (X25519MLKEM768, SecP256r1MLKEM768, X-Wing, hybrid KEM combiners), PQ certificate/signature handling in X.509 and TLS, PQ key serialization (seed vs expanded keys, PKCS#8/SPKI encodings from the IETF LAMPS drafts), constant-time and zeroization issues in PQ code, PQ test-vector coverage (NIST ACVP / Wycheproof / KAT vectors), PQ-related API misuse guards and error paths.
Use `git log --since=6.months -- <pq dirs>` and the open issues to find what maintainers are actively changing; recent PQ code is where real bugs and gaps live. Also look for spec-conformance gaps against FIPS 203/204/205 and the current IETF drafts (e.g. missing checks required by the standard, wrong encoding for a draft version the repo claims to support). Only fall back to non-PQ opportunities if the PQ code has nothing meaningful.
