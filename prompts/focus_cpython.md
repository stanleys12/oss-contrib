This repository is a flagship project: a merged fix here is worth more than ten merged fixes elsewhere, and its maintainers are flooded with low-value and AI-generated PRs. Find the ONE opportunity most likely to be merged and to be respected by a senior maintainer. Rank candidates by these criteria, strictly in this order:

1. **A real, demonstrable defect** (crash, wrong result, data corruption, resource leak, race, security or hardening gap, spec non-conformance) with a reproducer or a failing test you can write. No typo fixes, no lint/style cleanups, no docstring-only changes, no "modernisation", no dependency bumps, no drive-by refactors. If the only things you can find are that, report "nothing meaningful" instead.
2. **Small blast radius, high confidence**: a fix that a maintainer can verify in minutes and that touches one subsystem. Prefer a 20-150 line change with a test over a 500 line feature.
3. **Not already claimed**: check open PRs and issue assignees/comments for the same fix. Prefer issues confirmed by a maintainer (labelled as a bug, or with a maintainer comment saying "PRs welcome"/"needs fix") that nobody has taken. Report the issue number and what makes it unclaimed.
4. **Testable here**: this machine is macOS arm64 with 10 cores, ~45 GB free disk, no GPU, and no Docker or Linux containers (native macOS builds and tests only). Say exactly how the fix would be verified locally (unit test target, build target) and how long that takes. Skip opportunities that need a GPU, a cluster, or a multi-hour full build unless a narrow build/test target exists.
5. **Skip anything labelled `good first issue`** or aimed at newcomers: several of these projects forbid using AI tools on those, and they carry little weight anyway.

For each opportunity also record, in `notes`: the exact submission flow this repository uses (GitHub PR vs mailing list vs Gerrit/Phabricator), the CLA/DCO requirement, the project's written policy on AI-assisted contributions (quote the tag or sentence it requires, e.g. `Assisted-by:` trailer, a disclosure sentence in the PR body, "no AI commit messages", "no AI co-author trailer"), and whether an issue must exist first. Read CONTRIBUTING, the PR template, `Documentation/process/*` (kernel), `docs/` contributor pages, and any `AGENTS.md`/`CLAUDE.md` for this. Quote file paths.
